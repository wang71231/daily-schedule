# 每日课表

大学课表、体培课表、额外课时补录和月结工资。支持分钟/小时输入、手机布局、JSON 备份与恢复。

工资规则：有课时的月份基础工资 5000 元（含 40 小时），超过 40 小时部分按 65 元/小时；没有记录的月份不计工资。新密码至少 6 个字符。

## 两种运行方式

| 方式 | 数据在哪里 | 登录与多设备同步 |
| --- | --- | --- |
| [GitHub Pages](https://wang71231.github.io/daily-schedule/) | 当前浏览器的 IndexedDB | 无后台；不会同步到 GitHub 或其他设备 |
| Cloudflare Workers + D1 | 本机副本 + 云端数据库 | 密码登录、改密、断网待同步、版本冲突检查、云端历史 |

**GitHub 保存的是代码，不是课时数据库。** Cloudflare 部署步骤见 [部署说明](cloudflare/README.md)。只有实际部署、登录并显示“已同步到云端”，才能认为记录已上传。

## 记录与恢复

- 每次编辑用一个数据库事务保存，两个标签页同时编辑不同记录不会互相覆盖。
- 每次变更前保留完整本机快照，最多 100 份。打开“导出、备份与管理数据 → 保存历史”可下载或恢复；恢复前也会保存当前数据。
- 首次打开新版自动读取旧版 `localStorage`。旧键不删除；旧版“上次记录”也会作为恢复点保留。若数据损坏，暂停写入并提供原始导出，不把损坏数据当成空记录覆盖。
- 如果还有旧页面在后台记课时，会出现“合并旧版页面新记录”。合并保留当前冲突项，旧版完整内容另存入历史供核对。
- 导入 JSON 会先验证全部内容，再一次提交；缺少的记录补入，重复记录保留当前值。想完整回到某个版本，请从保存历史恢复。
- 托管版每次上传用云端版本号校验，并在同一事务保留上一版本。不同记录可自动合并；同一记录冲突时暂停，提供两端备份及明确的选择。
- 上传过程中继续编辑、断网、登录过期、存储满时，不会将未完成的操作标成已同步。

**本机历史也属于浏览器数据。** 清除网站数据、使用无痕窗口、卸载浏览器或换设备，都可能失去本机副本。请定期下载 JSON 备份；CSV 是结算表，不是完整恢复文件。不同网址、浏览器、PWA 使用环境可能拥有不同的数据空间。

## 从旧网址迁到云端

1. 在原来实际记课时的手机和浏览器打开旧 GitHub Pages，下载 JSON 备份，核对“全部课时记录”和月度课时。
2. 登录新托管网址，恢复该 JSON。等到显示“已同步到云端”。
3. 刷新，并在另一设备登录，核对记录条数、日期、课时和工资。
4. 保存原始 JSON，确认数据完整后再切换常用入口。不要先清理旧网站数据。

代码发布不会自动取走手机里的记录，也不会自动把旧家庭服务器的数据迁到 D1。

## 开发和测试

应用前端不依赖框架。现有 Python 服务保留作历史兼容方案；新部署使用 `cloudflare/worker.mjs`。

```sh
npm ci
npm test
python -m pip install -r tests/requirements.txt
python tests/test_browser.py
python -m unittest discover -s server -v
```

浏览器测试默认使用本机 Chrome，创建隔离的无界面测试上下文，不读取用户浏览器配置。可用 `TEST_BROWSER_CHANNEL` 切换测试浏览器。没有 Chrome 时需按 Playwright 文档配置测试浏览器。

本地 Cloudflare 联调使用独立测试 D1，步骤见部署说明，再执行 `python tests/test_hosted.py`。该脚本拒绝非本机网址，避免修改真实数据库。

## 主要文件

- `training.html`：体培课时界面；`state.js`：共同校验和三方合并规则。
- `storage.js`：本机事务、旧数据迁移、快照；`server/server-mode.js`：云端同步。
- `cloudflare/worker.mjs`：认证、API、版本历史；`cloudflare/schema.sql`：D1 表结构。
- `cloudflare/build.mjs`：只打包需要发布的页面和资源，不打包数据文件。
- `docs/data-reliability.md`：排查结论、已验证场景与限制。

真实 JSON 备份、数据库、密码、Cookie、私钥、`.dev.vars` 和 `.env` 不得提交 Git。
