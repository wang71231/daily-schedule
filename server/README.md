# 课表服务器版（本地准备）

此目录提供一个只用 Python 标准库的课时数据服务。页面、接口同源；课时记录、临时加课、历史课时和工资单价保存在 SQLite。原 GitHub Pages 课表仍可独立使用，当前阶段不切换线上入口。

## 本机启动

1. 运行 `python server/app.py hash`，输入自定密码，复制输出的完整哈希。
2. 在当前终端设置环境变量 `SCHEDULE_PASSWORD_HASH` 为该哈希。
3. 运行 `python server/app.py`，打开 `http://127.0.0.1:8090/`。

不要把密码或哈希提交到 Git。服务默认只监听 `127.0.0.1`，数据库默认位于 `server/schedule.db`，均可用 `SCHEDULE_HOST`、`SCHEDULE_PORT`、`SCHEDULE_DB` 环境变量调整。

## 手机旧数据迁移

1. **先在手机原 GitHub Pages 体培课表点击“备份数据”**，保存 JSON 文件。该文件只存在手机本地，不会自动出现在新服务器域名下。
2. 登录服务器版课表，在体培页点击“恢复备份”，选择刚保存的 JSON。
3. 等待页面显示“已同步到服务器”，刷新后核对“查看全部课时记录”、临时加课、历史课时和工资。
4. 核对无误后，再考虑将服务器版设置为主要入口。原页面和备份文件先保留。

## 同步规则

- 每次修改先写到本机缓存，再上传服务器；页面显示已同步、待同步或冲突状态。
- 服务器记录有版本号。若本机离线修改期间服务器也变更，自动上传会暂停，提供备份和显式合并按钮；同一条记录合并时本机值优先。
- 服务器当前无课时记录时，**不会自动上传浏览器缓存**。迁移必须用 JSON 文件明确导入。
- 不同网站的 `localStorage` 不相通；GitHub Pages 的旧记录无法由服务器版直接读取。

## 服务器部署前检查

- 使用 Tailscale 提供的 HTTPS 或其他可信 HTTPS 反向代理，将请求转发到服务器本机 `127.0.0.1:8090`，并设置 `SCHEDULE_HTTPS=1`。手机需要连上 Tailscale 才能访问 Tailscale 专用地址。
- 哈希只存于服务器的私有环境文件，文件权限设为 `0600`；服务用专用用户运行。
- 通过 `python server/app.py backup /目标目录/文件.db` 制作 SQLite 一致性备份，并安排每天自动执行；定期把备份复制到另一台设备。
- HTTPS 登录、导入、离线修改后重连、并发冲突及数据库备份恢复均需在真实服务器上复核，之后再迁移手机数据。
